# Persistent workflow learning implementation (2026-10-25)

User authorized implementation after the independent literature review. This branch starts at585d8cb and adds an opt-in controlled FIFO batch. Legacy defaults, historical artifacts and the primary workspace's seven edits are preserved.

`PersistentWorkflowEnv` combines eight released Alibaba DAG skeletons into disconnected components with prefixed node IDs and explicit FIFO execution. All requests arrive at reset. Adapter assignment is fixed by SHA-256 of source workflow/node over five compatible controlled adapters; it is modeled, not observed AI labels. One frozen vehicle must remain present throughout all96 NGSIM frames. Typed288MB capacity and dependency-safe LRU persist over the whole batch. Per-RSU serial loading uses128MB/s and0.05s/object; reserved bytes count against capacity before service readiness. These are simulated costs, not field measurements.

Public reward contract `persistent_fifo_batch_v1`:5 per completed request, minus integrated pending-request seconds,0.25 per GiB newly admitted model transfer, and5 per unfinished request at the finite horizon. No prepare/exploration bonus. All failures and unfinished requests stay in their original denominator. A finite task horizon terminates; an external training rollout cut retains bootstrap. Native reward components remain diagnostic fields only. Production state export/import is not implemented by this variant.

`DirectWorkflowGraphPPOAgent`, in `sa_ghmappo_agent.py`, is an explicitly named minimal graph PPO variant with direct masked actions, no hierarchy, teacher or auxiliary objective. It is not a renamed validated legacy SA-GHMAPPO. It is consumed only by the experimental runner and is not added to the live registry/formal benchmark. Same-input flat control is available with `use_graph=False` for subsequent bounded ablation.
