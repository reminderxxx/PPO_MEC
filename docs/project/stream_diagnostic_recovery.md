# 诊断日志的低内存核验与未运行单元补全

本流程针对日志消费者保留完整历史 payload 导致的内存增长。`sa_stage5c_credit_audit` 提供显式 `compact_joins=True`：每条完整记录仍执行原 schema、UID、mask、跨 seed、采样、优化器和终态校验；历史仅保留后续关联需要的字段。原始日志、返回报告和默认调用语义保持。紧凑历史不是采样、截断或降低检查标准，也不能证明算法不稳已修复。

失败的独占运行永久保留失败状态，禁止补写成功、复用 claim 或扩大资源上限。已经保存的配对证据可在独立合同下只读核验；原件 SHA、终态、失败上下文、逐会话摘要和保存文件均须绑定，输出只写新的派生目录。

`scripts/recover_stream_seed7.py` 的 `check` / `run` 只消费既有字节、JSON 和完整结构关联，不反序列化 tensor，不创建模型、环境或优化器。成功状态仅为 `RECOVERED_SEED7_ONLY_OBSERVER_PARITY`：原运行仍失败，其余 seed 仍是未运行。完整矩阵总结器继续拒绝原失败根目录。

回收限制为 512MiB RSS、1800秒墙钟、1500秒CPU和16MiB单行；完整结构校验前先做有界逐行读取。执行入口从预检开始约束资源，合同本身及输入、实现字节在末尾再次核验；回收不因大日志自动提高额度或重试。

`scripts/complete_stream_diagnostic.py` 的独立 `check` / `run` 仅允许补全原合同中从未运行的 seed 17/27。它绑定原合同、失败回执、已核验的 seed 7 派生回执与原始配对证据，并检查旧根目录不存在这两个 seed。它保留原 4-case 前缀、`training_budget=64`、CPU/RSS/时间/日志上限，从头执行各自 off/on；不重复 seed 7、不恢复旧 claim，不增加原合同的总训练会话上限。

两个入口均要求先冻结清洁源码和合同；入口交付本身不启动科学运行。纯 mock 测试验证拒绝边界，不能代替真实日志回收。实际合同、命令、资源计数、来源和结果留在私有 ignored `artifacts/`。

局部回收与补全结果必须分别保留，再由独立审查说明证据覆盖；不能把多个根目录改名为原整轮成功。观察器数值一致、日志结构完整、学习有效、尾部稳定和正式论文证据是不同判断。统一长训仍需独立决策，不因本工具修复自动启动。
