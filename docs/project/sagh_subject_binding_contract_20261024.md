# Subject/prediction binding diagnostic contract (2026-10-24)

This isolated candidate adds a pure diagnostic contract and a zero-interaction trace consumer. It does not change production environment, reward, policy, teacher, gates, losses, optimizer or training budget. The base is b5e1796e33d53c5b2f4eae295b2c12853d57c91b. No candidate has been integrated into live environment stepping.

`scripts/sagh_subject_binding.py` binds an episode subject, decision subject, prediction source/time and execution subject/time. Missing/mismatched subjects, stale/future snapshots and a disappeared subject are explicit attribution boundaries. A boundary stays latched until a recorded reset; the new vehicle is never silently treated as the same episode continuation. `guard_prepare_context` returns a private context copy for a bound subject, or a rejection reason. It does not modify original contexts/actions or rewards.

`tests/test_sagh_subject_binding.py` forbids environment construction/reset/step and mobility stepping. It covers unchanged same-subject paths, subject replacement, missing subjects, provenance/time faults, action 0 with/without RSU, production same-step/history/gap bookkeeping, deep-copy isolation, retention of failed and post-boundary rows and create-only output. Existing history adapter-mismatch behavior is deliberately preserved and separately tested.

`scripts/check_sagh_subject_binding.py --run-root EXISTING_COMPARISON --output-root NEW_DIRECTORY` reads all existing `variants/*/cells/*/seed*/steps.jsonl`, including all failures and tail rows. It reconstructs the legacy per-vehicle prediction lookup origin; this is not a native provider snapshot identity witness. It checks the frozen legacy prepare bookkeeping, compares exact private bound-path bookkeeping, retains every original reward component, and exports all transition bindings. Source/input hashes and zero-call caps are recorded before consumption; output is create-only. No filtered or candidate return, service gain, rollout or paper claim is computed. Private preview rejection must not be presented as a live environment repair.

Entry use is diagnostic only, outside the training/evaluation flow. New experimental exposure protocols, subject termination behavior, training, formal/holdout and any scientific gain evaluation remain separate work. Do not discard boundary rows, select windows by reward, reuse a new subject's tail as a successful continuation, or replace old curves/results. Detailed local results are referenced only by the main-workspace qualitative index.
