## 一阶问题

当前 v2 五动作只能在关联站执行，车端 adapter 未声明时动作 2 不可用。8 个开发窗口中，6 个窗口的固定关联车辆工作量超过其 RSU 的 120 帧理论最大计算量。若把各车完整 DAG 静态分配给全窗口持续可达的 RSU，忽略传输、缓存与 DAG 排序后，8 个窗口的最小单站负载峰值为 57.75–98.5 工作单位，均低于 120；这只是可行性上界，不是可实现奖励。每个开发车辆帧都有至少 2 个覆盖内 RSU，但旧动作不能选择第二站。

当前开发窗口的 7,680 个车辆帧中，因预测目标与关联站不同而允许动作 4 的仅 13 帧；最终执行轨迹无未完成请求的关联换站。因此本批开发窗口无法检验预测迁移增益。按训练窗口预先选定的多帧工作负载中，固定 action-4 规则虽能产生少量到站就绪，其奖励增量仍很小。行动优先级应是可控站点分配与真实缓存对象，随后再优化预测器和 PPO 训练预算。

目前选取的 Alibaba 工作流把所有节点映射到同一 `veh_base_v1` 和五个合成 adapter 标签；虽然 typed cache 有 base/adapter 字节及少量驱逐，跨 base 的装载、共享和替换并未被这个输入激活。以后检验 base-model cache 优势需要另立公开来源或明确合成的多 base 机会层，不能从单 base 结果外推。

## 拟冻结的控制对象

对每个活跃请求，每次决策明确给出以下三个控制分量；任何算法都使用同一个动作、约束和奖励合同：

1. **执行位置**：本车（仅在声明了匹配 base 与 adapter 时）、当前关联 RSU、或覆盖内候选 RSU。候选站列表按公开且稳定的 RSU ID 排序，动作掩码检查几何覆盖、模型就绪或可排队装载、工作流父节点状态及可达链路。不能把远站执行写成瞬时无成本的关联切换；上传输入、排队、回传输出与切换状态必须计时计费。
2. **模型缓存操作**：`none`、为当前可执行节点准备 base+adapter、或为 DAG 中已知的下一候选节点准备 base+adapter；同时指定目标 RSU。base 依赖、对象字节、装载队列与实际驱逐必须在 typed cache ledger 中逐项记账。先保留共同的依赖安全 LRU 为受控基线，再加入显式 eviction/admission 选择；只有后者确实受策略控制并赢得独立对照，才使用“model-cache 友好”优势表述。
3. **状态操作**：`none` 或把当前版本的 DAG/执行状态预复制到明确目标站。到站就绪必须由传输完成、版本一致和恢复成功共同判定。旧副本过期、占用链路和额外字节都是成本，禁止无成本 teleport。状态对象先使用声明的合成代理，实体模型恢复证据单独报告。

动作实现宜为分层/参数化掩码：慢层决定 cache admission 与未来 DAG 对象，快层选执行站，事件层决定状态预复制。必须先冻结候选站数量、动作编码、mask 与 checkpoint 版本，再让 SA-GHMAPPO、controller-level MAPPO、缓存方向 PPO 和强规则策略一起接入；不能只给主方法更强的物理动作。旧 `semantic_discrete_5` 和 v2 checkpoint 继续保留，不静默改义。

## 因果观察与方法增量

公共 actor 输入应提供当前车位置和工作流、覆盖内候选站几何、当前可见缓存/队列/链路摘要、按延迟到达的远站共享状态，以及因果预测的目标、ETA、置信度和来源。集中 critic 可见当前联合状态，但不能把未广播的远站状态或未来帧泄露到 actor。每个共享包的字节数、年龄、丢失与发送频率进入成本账本。

SA-GHMAPPO 的待验证增量是：图编码器读取 DAG 依赖和未来 adapter 需求；车辆运动预测器给出多步位置/候选 RSU 分布与不确定性；surrogate 估计候选站的缓存就绪、排队和迁移完成风险；分层 actor 协同决定预置、执行和迁移。MAPPO 对照获得同一原始观察和物理动作，采用匹配预算的普通 flat/controller CTDE 表达；再分别关闭 SA 的图、预测、surrogate、共享状态使用与缓存规划以识别贡献。

预测器先以因果常速度为冻结基线，在仅训练时间段训练小型 GRU/LSTM 候选并以开发集检查多步轨迹误差、RSU 目标命中率、提前量和校准。只有预测提前量足以覆盖模型/状态传输，且在机制活跃窗口产生净效益时才接入控制；不要以更复杂预测器名称代替收益证据。当前公共预测器未训练，SA 启动配置的辅助系数为 0，不能称其已经兑现学习型 surrogate。

## 环境与实验门槛

- 在训练数据上、**看策略奖励前**确定多帧任务、缓存工作集、候选站覆盖、容量可行性与未完成时的换站机会。开发集需同时包含可行容量和有迁移机会的窗口；训练/开发/正式/封存窗口按原始时间区间互斥。不得凭 SA 得分回头调窗口或成本。
- NGSIM 与 Alibaba 是跨源组合；输入/输出字节、base/adapter 大小、RSU 算力、链路速率及状态体积均为合成假设，须分别标注并通过实际模型与链路测量做敏感性分析。扩至 16 车 6 站时，车辆数、覆盖密度和每请求资源比单轴变化，不把规模变化与算法改动混成一个对照。
- 先用固定的最近关联、可达最轻载、反应式缓存、预置缓存、无预测、无共享状态等规则验证物理机制。冻结 reward：完成节点、未完成等待、车端计算、模型字节/链路帧、状态字节/链路帧和共享字节；完整请求完成率、违约/失败、p95 延迟及缓存命中/驱逐/无效预取同时作为主要终点，避免靠积累未完成 DAG 的中间节点获得表面高分。若修改 reward，先按任务 SLA 与实测成本定权，不按算法排名调权。
- 再做等 seed、等训练窗口、等交互量和等更新预算的 24/96/更高预算曲线；保存中途 checkpoint，比较 greedy 与采样策略、critic 拟合、动作分布和机制链。开发集只用于候选选择；冻结后才评正式集，hidden holdout 最后一次开启。若 SA 不能稳定超过 MAPPO 与强规则，不以调奖励权重或筛窗制造最高排名。

## 实现顺序与验收

1. **环境合同**：候选站执行和传输计账；测试同车在不同合法站的服务差异、非法越界、冷缓存、状态版本及可复算逐帧奖励。再加入未来 DAG base/adapter admission 与 eviction 控制。所有 agent 和 benchmark consumer 同步升级。
2. **机会协议**：训练/开发窗口的静态容量、覆盖与预测提前量预检；冻结候选选择规则和窗口独立性。按强规则证实可控动作有可测的净收益后才开始 RL 重训。
3. **算法**：在共同 v3 动作上先训练 MAPPO 与规则锚点，再加 SA 图/预测/surrogate 模块；独立消融每个模块。若 SA 不如对照，检查 actor 信息、信用分配和采样效率，保留负向结果。
4. **外推**：从未用于设计的 formal/holdout、预测失准、cache 容量与链路压力、16 车 6 站及真实成本校准。当前开发证据不支持论文“最高奖励”“收敛”或“model-cache 优势”结论。
