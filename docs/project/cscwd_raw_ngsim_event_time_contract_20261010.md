- Parent workload: `configs/experiment/calibrated_continuous_workflow_interface_repair_v3_manifest.json`. Use exactly `dev_01` (US-101), `regression_00` (Lankershim), and `regression_05` (US-101), in that order. These are already exposed development instances. - Mobility: the local raw NGSIM CSV at `data/raw/mobility/ngsim/Next_Generation_Simulation_(NGSIM)_Vehicle_Trajectories_and_Supporting_Data_20260329.csv`, read-only. Select rows by the manifest's exact `source_segment_id` and inclusive `Global_Time` bounds, and require all 24 timestamps at 100 ms spacing. A `Location` segment is normalized by the existing NGSIM provider's normalization rule. Record file size/hash, matching row count, time and frame bounds; do not commit raw positions.
- Vehicle selection is outcome-blind: choose the numerically smallest `Vehicle_ID` in the **first** source timestamp; require that same vehicle in every timestamp, with unique, monotonic frames. Validation failure excludes the frozen instance without replacement. Do not select by contact, action, reward or completion.
- `Global_Time` is source milliseconds; `Local_X/Y` are source feet. Convert time differences to seconds by `/1000` and coordinates to metres by `0.3048`. Reject inconsistent units, gaps, duplicate vehicle frames or nonfinite coordinates. Peachtree's observed 10-digit clock is not in this frozen input list pending unit verification. FHWA documents the 0.1 s sampling and field semantics: [NGSIM fact sheet](https://www.fhwa.dot.gov/publications/research/operations/its/06135/index.cfm), [data dictionary](https://ops.fhwa.dot.gov/publications/fhwahop08054/sect7.htm).
- Simulation geometry, not an observed RSU label: three circles with radius 10 m, at the first selected vehicle position and at +12 m and +24 m along source `Local_Y`; circle IDs map to existing `rsu_0/1/2`. Geometry uses only the first timestamp, independent of future trajectory or algorithm outcomes. Ties go to the smallest RSU ID. No coverage means no current RSU service.
- Keep workload DAG, typed cache, links, time costs, deadline, seed and `max_steps` from each manifest instance/config. The raw trace supplies time and position only; it supplies no RSU deployment, radio rate, queue, cache or workflow truth. Those remain the declared calibrated simulation assumptions.

## Event-time and public information

- Start the decision at the second source timestamp: the first two positions are available as history, so a velocity-only causal forecast is defined. Modelled step cost advances `clock_seconds`; the physical position is interpolated only between adjacent raw samples bracketing the accumulated elapsed time. The trace ends at its last timestamp; there is no end clamp or repeated last RSU. Trace exhaustion yields `truncated=True`, `terminated=False` unless the workflow already completed. A value learner must bootstrap on truncation, not mark it a terminal success.
- Actual position/contact is private environment state. Public `semantic_state` contains current position, history-derived velocity, fixed RSU geometry and a causal constant-velocity forecast. Replacing all future source positions or the hidden trace endpoint while preserving the observed prefix must not change the public state or action estimate at that decision. Forecast confidence is an uncalibrated fixed 0.5, never inherited from the future-derived synthetic route profile. The public `contact_budget_seconds` is a forecast, not realized future dwell. Public `calibrated_context.time_contract` has schema `raw_ngsim_event_time_v1` and `clock_seconds`, `deadline_seconds`, `remaining_deadline_seconds`, `contact_scope=current_rsu`. It also exposes common `vehicle_fallback_seconds` and `failed_service_seconds` for all methods. The true trace endpoint and remaining duration are environment diagnostics only, never policy-visible.
- A step is admitted only when its modeled transfer, model load, recompute, compute, state restore and service commit can finish within the actual current-RSU contact and remaining source interval. Vehicle fallback needs only source interval, not RSU contact. This is a **conservative atomic admission approximation** over the existing calibrated step model: rejected work changes no typed cache, bytes or DAG completion; the failed attempt consumes up to the configured failure time while the source trace lasts. No partial transfer, remote serving after contact, or arbitrary-length atomic success is inferred. Each accepted native step retains its existing separate byte/time accounts. Rejection and trace-end are explicit transition reasons.
- A predicted next-RSU target may inform prefetch/migration only when it is derived from prefix velocity and known geometry. Physical admission still requires completion before the **current** contact exit. This model has no independent target-RSU wireless path; it cannot validate a cross-boundary preparation protocol. That limitation must accompany all behavioral results.
